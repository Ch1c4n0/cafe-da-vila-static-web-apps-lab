Publicando o "Café da Vila" no Azure Static Web Apps

Um passo de cada vez. Sem pressa. Seu progresso fica salvo neste computador.

Como usar este manual

✅ Cada passo tem um quadrado "Concluí este passo" no final. Marque quando terminar.

🎯 Se muitas informações na tela te cansam, clique em Modo foco: aparece só um passo por vez.

    Passo 0 · Entender o que vamos fazer

    ⏱️ 5 min🧠 só leitura
    Objetivo: saber o "porquê" antes do "como". Nada para instalar ainda.

    O que é o Azure Static Web Apps?

    É um serviço da Microsoft que coloca seu site na internet de graça (no plano Free).

    Pense numa cafeteria:

    • 🪟 A vitrine = o site (páginas HTML, cores, imagens). É o que as pessoas veem.
    • 🧑‍🍳 O balconista = a API. Ele recebe pedidos e responde. Fica "escondido" atrás do balcão.
    • 🏢 O prédio = o Azure Static Web Apps. Ele guarda a vitrine e o balconista juntos.

    O caminho completo

    💻 Seu PCvocê escreve o código
    →
    🐙 GitHubguarda o código
    →
    ⚙️ GitHub Actionsrobô que publica
    →
    ☁️ Azuresite no ar
    →
    🌍 Pessoasacessam o link

    A parte mágica: depois de configurado, toda vez que você enviar uma mudança para o GitHub, o site se atualiza sozinho.

    A aplicação fictícia: "Café da Vila"

    Já está pronta na pasta D:\Static Web Apps\cafe-da-vila. Ela tem:

    • Uma página com o cardápio da cafeteria.
    • Um formulário para fazer um pedido.
    • Uma API com dois endereços: /api/cardapio (lista os itens) e /api/pedido (recebe o pedido e devolve um número).

    💡 Você não precisa entender o código para seguir este manual. Só seguir os passos.

    ⏱️ 10 a 30 min🔧 instalação
    Objetivo: ter 3 programas no PC e 2 contas na internet.
    O quêPara que serveOnde conseguir
    🟧 GitEnvia seu código para o GitHubgit-scm.com

    Como conferir se o Git e o Docker já estão instalados

    1. Aperte a tecla Windows ⊞ do teclado.
    2. Digite PowerShell e aperte Enter. Abre uma janela azul ou preta. Ela é o terminal.
    3. Copie o comando abaixo, cole no terminal (botão direito do mouse ou Ctrl+V) e aperte Enter:
      PowerShell
      git --version
docker --version

    👀 O que você deve ver: duas linhas parecidas com git version 2.xx e Docker version 2x.x. Os números podem ser diferentes. Tudo bem.

    ⚠️ Se aparecer "não é reconhecido como nome de cmdlet", aquele programa não está instalado. Instale pelo link da tabela, feche e abra o PowerShell de novo, e teste outra vez.

    ⚠️ O Docker Desktop precisa estar aberto (ícone da baleia 🐳 perto do relógio) para funcionar.

    Passo 2 · Conhecer as pastas do projeto

    ⏱️ 5 min🧠 só leitura
    Objetivo: saber onde fica cada coisa. Você não vai mexer em nada agora.
    D:\Static Web Apps\ ├── Manual-Static-Web-Apps.html ← este manual └── cafe-da-vila\ ← o projeto ├── app\ 🪟 A VITRINE (o site) │ ├── index.html a página │ ├── style.css as cores e o visual │ ├── script.js conversa com a API │ └── staticwebapp.config.json regras do Azure ├── api\ 🧑‍🍳 O BALCONISTA (a API) │ ├── package.json lista de "peças" da API │ ├── host.json configuração das Functions │ └── src\functions\ │ ├── cardapio.js responde em /api/cardapio │ └── pedido.js responde em /api/pedido ├── Dockerfile receita do container de teste ├── docker-compose.yml liga tudo com 1 comando └── README.md resumo do projeto
    🤔 Por que a API fica numa pasta separada?

    O Azure Static Web Apps sabe que tudo dentro de api é "balconista". Ele transforma esses arquivos em Azure Functions (pequenos programas que rodam só quando alguém chama). Você não paga servidor ligado o tempo todo.

    🤔 O que faz o arquivo staticwebapp.config.json?

    São regras para o Azure. No nosso caso: (1) qualquer endereço desconhecido mostra a página inicial; (2) a API usa Node.js versão 20.

    Passo 3 · Testar no seu PC com Docker

    ⏱️ 5 a 10 min🐳 Docker
    Objetivo: ver o site funcionando no seu computador, igual vai funcionar no Azure.
    1. Confira se o Docker Desktop está aberto 🐳.
    2. No PowerShell, entre na pasta do projeto. As aspas são obrigatórias porque o nome da pasta tem espaços:
      PowerShell
      cd "D:\Static Web Apps\cafe-da-vila"
    3. Ligue o projeto:
      PowerShell
      docker compose up --build
    4. Espere. Na primeira vez demora alguns minutos (o Docker está baixando as peças). Muitas linhas vão passar na tela. É normal.
    5. Quando aparecer algo como Azure Static Web Apps emulator started at http://0.0.0.0:4280, abra o navegador em:
      Navegador
      http://localhost:4280

    👀 O que você deve ver: uma página marrom e creme escrita "☕ Café da Vila", com 5 cartões no cardápio (Expresso, Capuccino, Pão de queijo, Bolo de fubá, Chá gelado).

    Teste o formulário: escreva seu nome, escolha um item e clique em Enviar pedido. Aparece uma mensagem verde com o número do pedido.

    🤔 O que está acontecendo por trás?

    O Docker criou uma "caixinha" (container) com o SWA CLI, um simulador oficial do Azure Static Web Apps. Ele liga o site e a API juntos, no mesmo endereço, como o Azure faz.

    Para desligar

    1. No PowerShell onde o projeto está rodando, aperte Ctrl + C.
    2. Depois rode:
      PowerShell
      docker compose down

    💡 Enquanto o container está ligado, se você mudar algo dentro da pasta app (por exemplo o texto do index.html), basta recarregar a página (F5) para ver.

    🟪 Boa hora para uma pausa. Você já tem o site funcionando no seu PC. Levante, beba água. O progresso está salvo.

    Passo 4 · Criar o repositório no GitHub

    ⏱️ 5 min🐙 site do GitHub
    Objetivo: criar uma "caixa vazia" na internet para guardar o código. Essa caixa se chama repositório.
    1. Abra github.com e faça login.
    2. No canto de cima, à direita, clique no + e depois em New repository.
    3. Preencha assim:
      CampoO que colocar
      Repository namecafe-da-vila
      DescriptionProjeto de estudo do Azure Static Web Apps (opcional)
      Public / PrivateQualquer um. Os dois funcionam.
      Add a README / .gitignore / licenseDeixe tudo DESMARCADO (já temos esses arquivos)
    4. Clique no botão verde Create repository.

    👀 O que você deve ver: uma página com o título "Quick setup" e um endereço parecido com https://github.com/SEU-USUARIO/cafe-da-vila.git. Deixe essa aba aberta.

    Passo 5 · Enviar o código para o GitHub

    ⏱️ 10 min🟧 Git no PowerShell
    Objetivo: copiar os arquivos do seu PC para o repositório que você acabou de criar.

    5.1 · Só se for a primeira vez que você usa o Git neste PC

    Diga ao Git quem você é (troque pelos seus dados, mantendo as aspas):

    PowerShell
    git config --global user.name "Seu Nome"
git config --global user.email "seu-email@exemplo.com"

    5.2 · Enviar o projeto

    Rode um comando por vez. Espere cada um terminar antes do próximo.

    1. Entrar na pasta:
      PowerShell
      cd "D:\Static Web Apps\cafe-da-vila"
    2. Transformar a pasta num projeto Git:
      PowerShell
      git init
    3. Marcar todos os arquivos para envio:
      PowerShell
      git add .
    4. Criar um "pacote" com uma etiqueta (commit):
      PowerShell
      git commit -m "Primeira versao do Cafe da Vila"
    5. Dar o nome main para a linha principal:
      PowerShell
      git branch -M main
    6. Ligar seu PC ao repositório. Troque SEU-USUARIO pelo seu usuário do GitHub (ou copie o endereço da aba do Passo 4):
      PowerShell
      git remote add origin https://github.com/SEU-USUARIO/cafe-da-vila.git
    7. Enviar:
      PowerShell
      git push -u origin main

    ⚠️ No último comando pode abrir uma janela pedindo login do GitHub. Escolha "Sign in with your browser" e autorize. É seguro: é o próprio Git pedindo permissão.

    👀 O que você deve ver: recarregue a aba do GitHub. Agora aparecem as pastas app, api e os outros arquivos.

    🤔 Vocabulário rápido

    commit = uma "foto" do projeto naquele momento, com uma etiqueta.
    push = empurrar (enviar) as fotos para o GitHub.
    origin = apelido do endereço do seu repositório.
    main = nome da linha principal do projeto.

    🟪 Pausa sugerida. Seu código já está seguro na internet. O próximo passo é o mais longo, então vale chegar descansado.

    Passo 6 · Criar o Static Web App no Azure

    ⏱️ 10 a 15 min☁️ portal do Azure⭐ passo principal
    Objetivo: criar o "prédio" no Azure e ligar ele ao seu repositório do GitHub.

    6.1 · Abrir a tela de criação

    1. Abra portal.azure.com e faça login.
    2. Na barra de pesquisa lá em cima, digite Static Web Apps e clique no resultado com esse nome.
    3. Clique em + Criar (ou + Create, se o portal estiver em inglês).

    6.2 · Preencher a aba "Básico"

    Vá preenchendo de cima para baixo. A tabela segue a mesma ordem da tela:

    Campo na telaO que fazer
    Assinatura (Subscription)Escolha a sua assinatura (geralmente só tem uma).
    Grupo de recursos (Resource group)Clique em Criar novo e escreva rg-cafe-da-vila. É uma "pasta" do Azure para organizar.
    Nome (Name)swa-cafe-da-vila
    Tipo de plano (Plan type)Free (grátis) ✅
    Região (se aparecer)Pode deixar a sugerida (ex.: East US 2). O site em si fica disponível no mundo todo.
    Origem (Source)GitHub
    Conta do GitHubClique em Entrar com o GitHub e autorize o Azure.
    Organização (Organization)Seu usuário do GitHub.
    Repositório (Repository)cafe-da-vila
    Branchmain

    6.3 · Detalhes do Build (a parte mais importante ⭐)

    Logo abaixo aparecem campos sobre onde ficam os arquivos. Preencha exatamente assim:

    CampoValorPor quê
    Predefinições de Build (Build Presets)CustomNosso site é HTML puro, sem framework.
    Local do aplicativo (App location)/appÉ a pasta da vitrine 🪟.
    Local da API (Api location)apiÉ a pasta do balconista 🧑‍🍳.
    Local de saída (Output location)deixe vazioNão temos etapa de "montagem", os arquivos já estão prontos.

    🟥 Cuidado: se o "App location" ficar errado, o site abre uma página padrão do Azure em vez do Café da Vila. Se isso acontecer, veja a seção Problemas comuns.

    6.4 · Finalizar

    1. Clique em Revisar + criar (Review + create).
    2. Confira o resumo e clique em Criar (Create).
    3. Espere 1 ou 2 minutos. Quando aparecer "A implantação foi concluída", clique em Ir para o recurso.

    ⚠️ Se aparecer algum campo que não está nesta tabela, deixe o valor padrão. O portal do Azure muda de visual de vez em quando, mas os campos principais são estes.

    🤔 O que o Azure fez sozinho agora?

    Ele colocou um arquivo novo no seu repositório do GitHub, dentro de .github/workflows/. Esse arquivo é a "receita" do robô GitHub Actions, que publica o site toda vez que você enviar mudanças.

    Passo 7 · Acompanhar a publicação

    ⏱️ 3 a 5 min de espera⚙️ GitHub Actions
    Objetivo: ver o robô trabalhando e confirmar que terminou bem.
    1. Vá na aba do seu repositório no GitHub e recarregue (F5).
    2. Clique na aba Actions (no menu de cima do repositório).
    3. Você vai ver uma linha com o nome "Azure Static Web Apps CI/CD".
    ÍconeSignificadoO que fazer
    🟡 bolinha amarela girandoTrabalhandoEsperar. Leva alguns minutos.
    ✅ check verdeDeu certo!Ir para o Passo 8.
    ❌ X vermelhoDeu erroClique nele para ler o erro e veja Problemas comuns.

    Passo 8 · Abrir o site publicado 🎉

    ⏱️ 2 min🌍 internet
    Objetivo: ver o Café da Vila funcionando na internet.
    1. Volte ao portal do Azure, na página do recurso swa-cafe-da-vila (tela Visão geral / Overview).
    2. Procure o campo URL. É um endereço parecido com https://palavra-palavra-0a1b2c3d4.azurestaticapps.net. Clique nele.
    3. Teste o cardápio e faça um pedido, como no Passo 3.
    4. Teste a API direto: no final do endereço, acrescente /api/cardapio e aperte Enter.

    👀 O que você deve ver: o mesmo site do seu PC, agora com cadeado 🔒 (HTTPS). Em /api/cardapio aparece um texto com chaves { }: é a resposta da API em formato JSON.

    💡 Esse link pode ser enviado para qualquer pessoa. Ele já funciona no celular também.

    Passo 9 · Fazer uma mudança e ver o site atualizar sozinho

    ⏱️ 10 min🔁 ciclo de trabalho
    Objetivo: aprender o ciclo que você vai repetir sempre: baixar → mudar → enviar → esperar → ver.
    1. Baixar a novidade do GitHub. Lembra que o Azure criou um arquivo lá? Seu PC ainda não tem ele:
      PowerShell
      cd "D:\Static Web Apps\cafe-da-vila"
git pull

      🟥 Não pule este item. Sem o git pull, o próximo envio dá erro (rejected).

    2. Mudar algo: abra app\index.html (no VS Code ou Bloco de Notas). Troque o texto O cafezinho mais gostoso da vila por O cafezinho mais gostoso do mundo! e salve (Ctrl+S).
    3. Enviar:
      PowerShell
      git add .
git commit -m "Muda o titulo da pagina"
git push
    4. Esperar: vá na aba Actions do GitHub e espere o ✅ verde (como no Passo 7).
    5. Ver: abra o link do site e recarregue (Ctrl+F5).

    👀 O que você deve ver: o título novo, "O cafezinho mais gostoso do mundo!". Você não precisou entrar no Azure. 🎉

    Passo 10 · (Opcional) Apagar tudo do Azure

    ⏱️ 3 min🧹 limpeza
    Objetivo: remover o site quando não precisar mais. No plano Free não há cobrança, mas é bom manter a conta organizada.
    1. No portal do Azure, pesquise Grupos de recursos (Resource groups).
    2. Clique em rg-cafe-da-vila.
    3. Clique em Excluir grupo de recursos, digite o nome para confirmar e clique em Excluir.

    🟥 Isso apaga o site da internet para sempre. O código continua no seu PC e no GitHub.

    📖 Glossário (palavras difíceis)

    PalavraSignificado simples
    APIO "balconista" do site: recebe pedidos e devolve respostas.
    Azure FunctionsPequenos programas que só "acordam" quando alguém chama. É como a API roda no Azure.
    ContainerUma caixa isolada com tudo que o programa precisa para rodar.
    Docker ComposeUm arquivo que liga containers com um único comando.
    RepositórioPasta do projeto guardada no GitHub, com histórico de mudanças.
    CommitUma "foto" do projeto com uma etiqueta explicando a mudança.
    Push / PullEnviar para o GitHub / Baixar do GitHub.
    GitHub ActionsRobô do GitHub que executa tarefas sozinho, como publicar o site.
    CI/CDNome técnico para "testar e publicar automaticamente".
    Grupo de recursosPasta do Azure que agrupa coisas de um mesmo projeto.
    JSONFormato de texto com { } que programas usam para trocar dados.
    HTTPS 🔒Conexão segura. O Azure liga isso de graça para você.
